# AI議事録（スマホ用Webアプリ）

会議をスマホで録音し、「会議を終了して議事録を作成」を押すと、文字起こし・要約・PDF作成までを**スマホの中だけで**行うWebアプリです。
音声や議事録の内容は外部に送信しません。インターネットは、AIモデルを初回にダウンロードするときだけ使います。

- 費用: 0円（無料のホスティングで公開でき、AIの利用料もかかりません）
- 対応: iPhone・Android（ブラウザで開いて「ホーム画面に追加」で使う）
- Mac・App Store・Google Play は不要

## できること

| 機能 | 内容 |
|---|---|
| 録音しながら文字起こし | 話した内容がほぼリアルタイムで画面に出ます。録音中に処理しておくので、終了後の待ち時間が短くなります |
| 音声ファイルから作成 | iPhoneの「ボイスメモ」などで録った音声（m4a / mp3 / wav）を読み込んで議事録にできます |
| 要約 | 会議名・概要・議題・決定事項・ToDo（担当・期限）・主な議論を作成します |
| 編集 | 作成された内容を画面で直してから PDF にできます（自動保存） |
| PDF | A4・日本語フォント埋め込み。共有シートから LINE・メール・ファイル保存へ渡せます |
| 履歴 | 過去の議事録は端末内に保存され、あとから再編集・再出力できます |

## 仕組み

```
マイク / 音声ファイル
   │ 16kHzに変換
   ▼
[文字起こし]  sherpa-onnx（WebAssembly）＋ ReazonSpeech k2 v2（日本語特化）
   │ 無音で区切った発話ごとに、余白の取り方を変えて2回文字起こしし、長い方（言葉を落としていない方）を採用
   ▼
[要約]  GPU（WebGPU）のある端末 → WebLLM で要約AIを実行（速い）
        GPUのない端末          → wllama（llama.cpp）で同じ要約AIをCPUで実行（遅いが動く）
        会議全体（約1万字まで）を1回でAIに渡して議事録にする。長い会議は分けて処理してまとめる
   ▼
[編集画面] → [PDF]  pdfmake ＋ BIZ UDPゴシック
```

### 使っているAIを選んだ理由（実際に比べた結果）

- **文字起こし**: 日本語の音声150件（JSUT・ReazonSpeech・Common Voice）で文字誤り率を比べ、ReazonSpeech k2 v2 が最も正確でした（約5〜7%）。NVIDIA Parakeet 日本語版（6〜9%、2〜4倍遅い）、SenseVoice（日本語では使えず）より良い結果です。
- **要約**: 実際の会議音声（約5分）の文字起こしと解答例で比べました。
  - Qwen3.5 4B は決定事項（高橋さんのヘルプ、毎朝9時から15分の情報共有など）をすべて拾い、宿題もおおむね正確でした → GPUのあるPCで使用。
  - Qwen3.5 2B は決定事項・要点はおおむね拾えますが、宿題の担当者を取り違えやすいです → スマホ・GPUのない端末で使用（内容は確認・修正してください）。
  - Gemma 2 2B 日本語版は取りこぼしが多く、Qwen3.5 0.8B はほぼ使えない出来だったため採用していません。
  - 担当者の取り違えは、文字起こしに「誰が話したか」が含まれないことが主な原因です。
- **要約の工夫**: 会議全体を1回でAIに渡す／音声認識の誤変換を文脈で直させる／「決定・依頼・引き受け」らしい発言を目印として添える／4Bでは宿題だけをもう一度確認する、を組み合わせています。

### 要約AIの設定

| 設定 | モデル | 初回ダウンロード | 向いている端末 |
|---|---|---|---|
| 自動（既定） | GPUのあるPCは「高精度」、それ以外は「標準」 | — | — |
| 標準 | Qwen3.5 2B | GPU版 約1.1GB / CPU版 約1.3GB | スマホ・GPUのないPC |
| 高精度 | Qwen3.5 4B | 約2.4GB | GPUのあるPC |
| AIを使わない | キーワードと言い回しから抜き出す簡易要約 | なし | すべての端末 |

- GPUのない端末ではCPUで動かすため、要約に時間がかかります（端末の性能と会議の長さによります）。作成画面に「読み込み ○%・残り約○分」「書いた文字数」を表示し、待てないときは「AI要約をやめて、簡易要約ですぐ作成する」ボタンで切り替えられます（あとで「要約を作り直す」からAI要約をやり直せます）。
- CPU版は、複数のCPUコアを使えるよう、Service Worker で「クロスオリジン分離」のヘッダーを付けています（GitHub Pages ではサーバー側で設定できないため）。
- 作成中は画面の自動ロックを止めます。画面をロックしたり別のアプリに切り替えたりすると、ブラウザが処理を止めることがあるためです。
- メモリや保存容量が足りずにAIが失敗したときは、自動でやり直します（GPUで駄目ならCPUで試す）。
- それでもブラウザが処理を止めた場合は、次に開いたときに理由を案内し、「続きから作成」できます。文字起こしは保存されているので、録音し直す必要はありません。

## マイク・外部機器

スマホ内蔵マイクのほか、次のような外部機器も使えます（ブラウザがマイクとして認識できるもの）。

| 使い方 | 例 | 補足 |
|---|---|---|
| スマホ ＋ 外部マイク | USB-C / Lightning のマイク、ピンマイク、Bluetoothヘッドセット | つなぐとスマホが自動で切り替えます。Bluetoothは音質が落ちることがあります |
| PC ＋ 会議用マイク | USBスピーカーフォン、USBマイク | ChromeやEdgeでアプリのURLを開いて使えます |
| PC ＋ 音声取り込み機器 | オーディオインターフェース、ミキサーのUSB出力 | 2チャンネル以上の機器は全チャンネルを混ぜて使うので、どの入力端子につないでも録音できます |

- 録音画面の「マイク」で、録音中でもマイクを切り替えられます。選んだマイクは次回も使います（設定画面でも選べます）。
- 15秒以上音が入っていないと、接続や選択の確認をうながす表示が出ます。
- 専用の会議用マイクやミキサーを使う場合は、設定の「音声の自動調整」をオフにすると機器の音をそのまま使います（スマホ内蔵マイクではオンがおすすめ）。
- **文字起こしの精度を一番左右するのはマイクと話者の距離です。** 大きな会議室では、会議用スピーカーフォンや外部マイクを使うと精度が大きく上がります。

## 動作環境と注意点

- **AI要約は WebGPU（GPU）があると速く動きます。** iPhone は iOS 26 以降の Safari、Android は新しめの Chrome が目安です。WebGPU のない端末ではCPUで動かします（時間がかかります）。WebAssembly も使えない古いブラウザでは簡易要約になります。
- **録音中は画面を開いたままにしてください。** Webアプリの制約で、画面ロックや別アプリへの切り替えで録音が止まることがあります（自動ロックは止めています）。長い会議で心配な場合は、ボイスメモで録音して「音声ファイルから作成」を使う方法もあります。
- 文字起こしモデル（約160MB）と要約AIは初回にダウンロードします。Wi-Fi 推奨です。
- AI要約の途中でアプリが落ちた場合（メモリ不足）、次回起動時に軽い設定への切り替えを案内します。

## 開発・動作確認

Node.js 20.19 以上（または 22.12 以上）が必要です。

```bash
npm install
```

```bash
npm run dev
```

ブラウザで http://localhost:5173 を開きます。WebGPU が使える PC の Chrome なら AI要約まで試せます（初回に約2.4GBをダウンロード。使えるかは設定画面の「この端末」で確認できます）。

`public/vendor/` の外部ファイル（文字起こしエンジン・VADモデル・フォント）はリポジトリに含めています。取り直す場合は次を実行します（取得元はコミット固定）。

```bash
npm run fetch-vendor
```

### スマホで試す（PCと同じWi-Fi）

マイクは HTTPS でないと使えないため、自己署名証明書で起動します。

```bash
npm run dev:lan
```

表示された `https://192.168.x.x:5173` をスマホで開き、証明書の警告で「詳細を表示 → このWebサイトを閲覧」（iPhone）などを選びます。Windows のファイアウォール確認が出たら許可してください。

## 無料で公開する

```bash
npm run build
```

できた `dist` フォルダを、次のどちらかで公開します（どちらも無料・HTTPS対応）。

- **Cloudflare Pages（おすすめ）**: ダッシュボードの「Workers & Pages → 作成 → Pages → アセットをアップロード」で `dist` をドラッグ＆ドロップするだけです。
- **GitHub Pages（このリポジトリの設定）**: `main` に push すると、[.github/workflows/deploy.yml](.github/workflows/deploy.yml) が自動でビルドして公開します。初回だけ、GitHub のリポジトリ画面で「Settings → Pages → Source」を「GitHub Actions」にしてください。公開URLは `https://<ユーザー名>.github.io/<リポジトリ名>/` です（サブパスでも動くよう相対パスでビルドしています）。

公開したURLを配れば、各自のスマホで開いて「ホーム画面に追加」するだけで使えます。

## 使用しているソフトウェア・モデル

| 用途 | 名前 | ライセンス |
|---|---|---|
| 文字起こしエンジン | [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（WebAssembly版） | Apache-2.0 |
| 文字起こしモデル | [ReazonSpeech k2 v2](https://huggingface.co/reazon-research/reazonspeech-k2-v2) | Apache-2.0 |
| 音声区間検出 | Silero VAD | MIT |
| 要約AIの実行（GPU） | [WebLLM](https://github.com/mlc-ai/web-llm) | Apache-2.0 |
| 要約AIの実行（CPU） | [wllama](https://github.com/ngxson/wllama)（llama.cpp） | MIT |
| 要約モデル | Qwen3.5 2B / 4B | Apache-2.0 |
| PDF | [pdfmake](https://github.com/bpampuch/pdfmake) | MIT |
| フォント | BIZ UDPゴシック | SIL OFL 1.1 |

モデル本体は配布物に含めず、利用者の端末が Hugging Face から直接ダウンロードします。

## ファイル構成

```
public/
  asr-worker.js         文字起こしワーカー（VAD＋認識）
  recorder-worklet.js   マイク音声の取り出し
  vendor/               sherpa-onnx・Silero VAD・フォント
src/
  config.ts             使用モデルの定義（差し替えはここ）
  asr/                  モデルのダウンロード・ワーカーとのやり取り
  audio/                録音・ファイル読み込み・16kHz変換
  summarize/            要約AI（llm.ts）と簡易要約（rules.ts）
  pdf.ts                PDF作成・共有
  ui/                   画面（一覧・録音・作成中・編集・設定）
scripts/
  fetch-vendor.mjs      外部ファイルの取得
  gen-icons.mjs         アイコン生成
```
